# Design notes

How the profile is put together, and how to change it without breaking it.

## Concept: a system blueprint

The profile reads like the drawing of a working system. One signal line, cyan turning to violet, runs through every asset: it enters the hero as a request, crosses the API hub and ends at an agent node; in the system map it carries requests across the layers; in the git rail it is the feature branch that gets reviewed and merged. Violet always means AI.

The system map is the one bold piece. Everything else is kept quiet so it stands out.

## Tokens

| Token  | Value     | Use                                      |
|--------|-----------|------------------------------------------|
| void   | `#080C16` | Card surface                             |
| panel  | `#111827` | Raised surfaces (layer cards)            |
| line   | `#1E293B` | Hairlines, borders, inactive traces      |
| ink    | `#F8FAFC` | Primary text and icons                   |
| mist   | `#94A3B8` | Secondary text                           |
| dim    | `#475569` | Tertiary marks, separators               |
| signal | `#67E8F9` | Request flow, primary accent             |
| violet | `#A78BFA` | AI, agents, merges                       |

All defined once in `scripts/lib/svg.mjs`.

## Typography

- **Geist** (400, 500, 600) for names, headings and prose inside the artwork.
- **JetBrains Mono** (400) only where the content is technical: the stack line, legends, dates.

GitHub serves README images through `<img>`, which never loads web fonts and blocks external requests from inside the SVG. The generators convert every string to outlines with `opentype.js`, so the type renders identically on every device. The text is still exposed to assistive technology through each SVG's `<title>`/`<desc>` and the `alt` attribute in the README.

## Why dark cards on both themes

Each asset is a self-contained dark card with a 24px radius and a hairline border. On GitHub's dark theme it blends in; on the light theme it reads as a deliberate object on the page, like a product screenshot. This avoids keeping two colour variants in sync. The section divider is the exception: it is transparent and uses mid-tone slate, which is legible on white and on near-black.

## Responsive behaviour

Text inside an SVG scales with the image, so a 1200px-wide asset becomes unreadable at phone width. Every asset that carries text has a compact variant, served with:

```html
<picture>
  <source media="(max-width: 640px)" srcset="assets/hero-compact.svg">
  <img src="assets/hero.svg" width="100%" alt="…">
</picture>
```

GitHub's sanitizer keeps `media` on `<source>` (checked with the `POST /markdown` API). Clients that ignore `<picture>` get the wide `<img>`. Nothing uses fixed widths, so there is no horizontal scrolling.

## Motion

Animation is CSS inside the SVG (GitHub does not run JavaScript, and CSS in an image SVG does run). There is one load sequence per asset (traces draw in, nodes and text fade in over about 1.5 s), then two ambient effects: a slow drift of the background light and a short pulse travelling along the signal line every few seconds. Nothing blinks or flashes.

`@media (prefers-reduced-motion: reduce)` turns all of it off. Every animated element rests in its final, fully visible state, so the static rendering is the complete design. SMIL is not used because it ignores that media query.

## Making changes

```bash
npm ci
npm run build                          # hero, system map, divider
GITHUB_TOKEN=$(gh auth token) npm run activity   # activity card
```

Copy lives at the top of `build-assets.mjs` (`NAME`, `ROLE`, `STACK`, `CLAIM`, `LAYERS`). Layout constants are next to each function. Keep the `alt` text in `README.md` in sync when the copy changes.

## Activity workflow: permissions and dependencies

- Runs daily at 05:17 UTC and on manual dispatch.
- Workflow-level `contents: read`; the single job raises it to `contents: write` only to commit the two regenerated SVGs.
- Data comes straight from `api.github.com/graphql`. No third-party stats service is involved, so nothing can go down or rate-limit the profile.
- Contribution figures come from the contribution calendar, which includes anonymized private contributions because "Include private contributions on my profile" is enabled. Commit and pull request totals are not shown: the API only counts public repositories for those, which would contradict the calendar total.
- The language mix includes private repositories, which `GITHUB_TOKEN` cannot see. Because the repository is public, `scripts/languages.json` stores only what the card shows: the top five languages plus "Other", as shares rounded to 0.5% (no byte counts). It is only refreshed when a `STATS_TOKEN` secret exists: a fine-grained personal access token with access to all repositories and only **Metadata: read-only**. Without it, the snapshot is reused. To refresh it locally: `GITHUB_TOKEN=$(gh auth token) REFRESH_LANGUAGES=1 npm run activity`. No repository name is stored or rendered.
- The card has no timestamp, so the workflow only commits when the numbers change. Commits are authored by `github-actions[bot]` and do not count as personal contributions.
- Actions are pinned to commit SHAs.
- Dependencies (dev only, used at build time): `opentype.js`, `simple-icons` (CC0 brand glyphs), `@fontsource/geist-sans` and `@fontsource/jetbrains-mono` (SIL Open Font License).
